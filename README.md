# Cost-to-Serve & RTO Risk Analyzer

An end-to-end logistics analytics pipeline combining predictive modeling, causal
inference, and uncertainty simulation to answer a real operational question:
**where is cost-to-serve breaking down, and should a shipping-subsidy policy be
kept or removed?**

**[Live Demo](#)** *(deploy your own copy — see Deployment below)* | **[Run Locally](#running-locally)**

## ⚠️ Data disclosure

All data in this project is **synthetic**, generated by `src/data_generator.py`
with explicit, documented parameters (see inline comments). It is calibrated to
be internally consistent and realistic, not sourced from any real company. Every
number in the dashboard is traceable back to an assumption in that one file.

This is a deliberate choice: the goal of this project is to demonstrate
**methodology** (leakage-safe ML evaluation, causal inference, uncertainty
quantification) end-to-end, on a dataset where the "true" answer is known and
can be used to validate that each method actually recovers it.

## What this project does

1. **Cost-to-Serve Heatmap** — identifies which shipping corridor has runaway
   logistics costs and delay rates relative to order value.
2. **Delay/Cancellation Risk Model** — an XGBoost classifier predicting risk at
   order-placement time, benchmarked honestly against a Logistic Regression
   baseline using a **time-based train/test split** and **SMOTE applied only to
   training data** (both deliberate choices to avoid inflating reported
   accuracy with leakage).
3. **Causal Impact of a Shipping Promotion** — a Difference-in-Differences
   analysis isolating the true causal effect of a free-shipping promotion on
   order value, validated by recovering a known ground-truth effect from the
   synthetic data (recovered ₹193 vs. a true effect of ₹180).
4. **Policy Simulator** — a Monte Carlo simulation that chains the causal
   estimate's own uncertainty into a full distribution of outcomes for a
   subsidy-removal decision, rather than a single-point estimate.

## An honest finding, reported as-is

XGBoost does **not** materially outperform Logistic Regression on this dataset
(confirmed via 5-fold cross-validation: 0.706 vs. 0.700 AUC). This is reported
honestly rather than adjusted until the "expected" result appeared — disciplined
benchmarking should decide model choice, not an assumption that more complex
models are always better.

## Methodology notes

- **Time-based split**: the model is evaluated only on orders that occurred
  *after* the training period, mirroring real production conditions.
- **SMOTE on training data only**: class-imbalance correction is never applied
  to test data, which would otherwise optimistically bias reported metrics.
- **Causal inference, not just correlation**: the DiD design uses untreated
  corridors as a control group to isolate the promo's true effect from
  seasonality and corridor-level differences.
- **Chained uncertainty**: the policy simulator propagates the causal
  estimate's own confidence interval into the final decision, rather than
  treating a point estimate as certain.
